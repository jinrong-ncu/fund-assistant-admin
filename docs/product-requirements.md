# 估值助手管理后台 V2 产品需求文档 (PRD)

## 1. 文档定位与产品目标
「估值助手」是一款微信小程序，为基民提供基金估值、持仓盈亏记录、买卖点交易记录、自选关注及市场行情追踪等核心工具能力。

**管理后台 V2 (Fund Assistant Admin V2)** 是面向开发与运营人员的独立 Web 管理控制台，核心目标为：
1. **全景数据洞察**：透视小程序注册用户、持仓体量、交易活跃度及系统整体运行状态。
2. **安全运营干预**：支持在极端数据异常、脏数据或用户求助时，由管理员核实并进行用户持仓重算、流水修正，全程强制审计留痕。
3. **内容敏捷发布**：对小程序内的热门基金、版本更新日志、社群交流与作者支持等动态内容实现分钟级热更新。
4. **行情深度编排 (Layout Builder)**：构建所见即所得、版本化发布的行情结构编排系统，打通东方财富权威股票标的库。
5. **合规提审与系统治理**：提供一键提审模式、安全中性模式、OCR 开关、多级运维监控，保障小程序在微信平台的稳定合规运行。

---

## 2. 用户角色与权限体系 (RBAC)

虽然初期主要由单人负责开发和运维，但系统底层设计必须支持完整的多角色扩展能力，UI 层严禁硬编码单一角色逻辑。

| 角色代码 | 角色名称 | 权限描述 | 适用场景 |
| :--- | :--- | :--- | :--- |
| `admin` | 超级管理员 | 拥有全站所有功能权限，包括系统开关、流水增删改、持仓重算、配置发布、人员管理 | 核心系统所有者 / 开发者 |
| `operator` | 运营人员 | 允许查看业务数据、处理反馈、编辑热门内容/更新日志/交流资源，不可操作高风险系统开关与底层流水 | 日常内容运营 / 客服处理 |
| `readonly` | 只读审计员 | 拥有所有页面与数据的查看权限，禁止任何数据修改、删除或发布操作 | 外部审计 / 观察员 / 临时排查 |

## 3. 功能模块详细需求与业务语义

### 3.1 概览工作台 (Overview / Dashboard)
* **核心指标卡片 (MetricCard)**：
  * **全部用户**：系统累计注册微信用户数。
  * **今日新增**：自当天 00:00:00 至今新增注册用户数。
  * **有金额记录用户**：至少拥有 1 条有效持仓记录的用户数（体现核心活跃资产）。
  * **有关注清单用户**：自选基金库中至少有 1 只基金的用户数。
  * **待处理反馈**：处于 `open` / `pending` 状态的用户反馈数量与历史总反馈数。
  * **启用热门内容**：当前面向小程序展示中的热门推荐基金数量。
* **基础设施健康状态摘要 (Infrastructure Health Summary)**：
  * 每 60 秒定期检测 API 服务、Supabase PostgreSQL 数据库、Redis 缓存服务的存活连通性。
  * 提供快捷跳转至独立 `/system/health` 详情页的入口。
* **关键小程序运行状态快照 (Feature Snapshot)**：
  * 只读展示当前 `show_market_indices`（行情指数展示）、`personal_safe_mode`（安全展示模式）、`review_mode`（提审模式）、`ocr_enabled`（OCR 截图识别）的开闭状态。
  * 提供直达「系统设置」对应锚点的快捷入口，工作台自身不做表单提交。

### 3.2 用户与资产管理 (Users)
* **用户检索与分页 (User Table)**：
  * 支持按 `user_code`（系统分配的用户编号）、`nickname`（微信昵称）、`openid` 进行复合模糊检索。
  * 分页状态（page, pageSize）与搜索关键字（search）全部同步至 URL Query 参数。
  * 支持点击持仓数、关注数、反馈数、注册时间、最后活跃时间表头切换升降序；排序作用于全部匹配用户后再分页，默认注册时间降序，排序状态同步至 URL。
* **用户全景抽屉 (User Detail Sheet)**：
  * **基本信息**：头像、昵称、编号、注册时间、最后活跃时间，以及提供一键复制按钮的 `openid`。
  * **持仓记录 (Holdings)**：展示用户持仓代码、名称、当前持有金额、成本金额、持有份额与更新时间。
    * **重算功能 (Recalculate Holdings)**：针对指定标的，依据该用户全量历史流水从零重新执行复权计算。属于高风险操作，操作前必须弹出确认提示并强制填写操作原因，服务端执行后记录审计日志。
  * **交易流水 (Transactions)**：展示买入/卖出日期、基金代码、交易类型（买入/卖出）、交易金额、成本金额、交易份额、交易时净值及备注。
    * **编辑/删除流水**：必须在服务端单个原子事务内完成“修改流水记录 + 重新计算对应持仓汇总 + 记录操作审计”。必须输入原因。
  * **关注清单 (Watchlist)**：展示自选基金代码、名称、类型及加入自选时间。
  * **反馈历史 (User Feedback)**：展示该用户在小程序提交的所有历史反馈记录。

### 3.3 反馈工单闭环 (Feedback)
* **列表与筛选**：支持按处理状态（`open` 待处理、`processing` 处理中、`resolved` 已解决、`ignored` 已忽略）、优先级（`low` 低、`normal` 普通、`high` 高）筛选与分页浏览。
* **工单流转与管理员处理备注**：
  * 查看完整反馈内容、用户提交时间与用户信息。
  * 变更状态和优先级时，允许填写最高 500 字的处理备注（`admin_note`）。
  * 状态流转操作服务端自动产生审计记录。

### 3.4 运营内容中心 (Operations)
拆分为三个独立的功能子模块，消除单页大表单杂糅：
* **热门推荐 (Hot Funds)**：
  * 字段：基金代码（`fund_code`）、基金名称（`fund_name`）、排序权重（`sort_order`）、启用开关（`enabled`）。
  * 支持增删改查、即时启用/停用与排序调整。
* **版本更新日志 (Changelog)**：
  * 字段：版本号（`version`）、发布日期（`release_date`）、是否最新版本（`is_latest`）、更新条目列表（结构化数组 `items: Array<{ type: string; content: string }>`）。
  * 业务约束：**全局同一时刻最多只能有 1 个 `is_latest = true`**，服务端事务级校验与自动排他处理。
* **交流与支持资源 (Resources)**：
  * 字段：分类（`community` 交流社群 / `support` 支持赞赏）、渠道标识（`channel`，如 `wechat_group`、`author_reward`）、标题、说明、图片 URL、点击动作（`preview_image` 预览图片、`copy_text` 复制文字、`navigate` 小程序内跳转）、动作附带值（`action_value`）、排序权重、启用开关。
  * 表单需根据 `action_type` 动态展示对应辅助文案与输入控件。

### 3.5 行情系统与编排中心 (Market)
系统技术复杂度最高模块，必须拆分为 **股票标的池 (Stock Pool)** 与 **页面编排器 (Layout Builder)** 两部分：
* **股票标的池 (Stock Pool)**：
  * **东财联想搜索**：输入代码或中文名（如 `NVDA`、`英伟达`），后台代理调用东方财富 API 返回标准证券候选列表。
  * **权威解析入库**：点击入库后，服务端向东财二次拉取完整元数据（代码、市场类型、交易所、`secid`、权威中文名称），入库落盘。**禁止前端手工填入或篡改股票元数据**。
  * **标的刷新**：支持重新从东财同步更新证券元数据。
  * **引用保护删除**：删除股票前，服务端执行深度引用检测（检查顶部 Tickers、Tab 各模块 Modules 是否仍在引用）。若存在引用，**强制拒绝删除**，并明确返回“被哪些 Tab/模块引用”，禁止返回模糊的拒绝信息。
* **行情布局编排器 (Layout Builder)**：
  * **层级体系**：`Page` -> `Tickers`（顶部滚动指标）+ `Tabs`（标签页）-> `Sections`（模块分组）-> `Modules`（数据模块）。
  * **模块计算类型**：
    * `DIRECT`（单标的直读）：严格绑定 1 只股票/指数。
    * `AVERAGE`（成分平均）：至少绑定 2 只成分股，后台聚合计算平均表现。
  * **草稿与版本发布机制 (Draft & Publish)**：
    * 编辑界面提供脏状态检测（Dirty State）与未保存告警。
    * 采用 **Draft（草稿暂存） -> Validate（全量校验） -> Publish（原子化生效）** 流程。
    * 每次发布时生成全局版本号（自增），记录完整快照并产生审计日志。线上小程序永远只读取已发布的确定版本快照，杜绝半保存脏数据。

### 3.6 系统合规与配置管理 (Settings & System)
* **设置项分类管理**：
  * **审核与合规 (Review & Compliance)**：
    * `review_mode`（提审模式）：开启后隐藏新增入口并暂停截图识别。高风险开关，必须使用二次确认弹窗（AlertDialog）说明影响后方可提交。
    * `personal_safe_mode`（安全中性模式）：切换中性文案，规避监管限制。
  * **功能特性开关 (Features)**：
    * `ocr_enabled`（截图 OCR 识别开关）。
    * `show_market_indices`（金额记录页行情指数显隐）。
    * `support_entry_enabled`（“我的”页面支持/赞赏入口显隐）。
  * **资源配置 (Resources)**：
    * `community_qr_code`（社群二维码图片地址）。
    * `support_qr_code`（赞赏支持二维码图片地址）。
  * **高级通用配置 (Advanced)**：支持扩展性 Key-Value 动态读取与回车保存。

### 3.7 独立健康检查页 (System Health)
* 详细展示 API、Supabase PostgreSQL、Redis 各服务组件的响应延迟、配置状态及服务角色权限连通性。支持手动触发健康巡检。

### 3.8 操作审计中心 (Audit Logs)
* **全站写操作自动捕获**：服务端统一截获，严禁依赖前端主动上报。涵盖流水修改、删除、重算、反馈流转、内容编辑、开关变更、股票池与行情发布。
* **审计属性**：操作时间、操作管理员 ID/Email、IP 地址、操作动作类型、目标资源类型、目标 ID、操作原因（强制填写）。
* **变更结构化 Diff**：详情侧边栏提供 Metadata 概览以及基于新旧 JSON 的结构化 Diff 视图（明确区分新增、删除与修改字段），支持展开完整原始 JSON。
